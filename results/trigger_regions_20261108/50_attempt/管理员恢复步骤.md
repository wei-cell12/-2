# 50服务器GPU4定向恢复交接

本次只处理本项目失败试跑产生的PID35437及GPU4。其他GPU上有用户tyb的运行任务，不得停止、卸载驱动、重启服务器或扩大重置范围。

## 已核实的状态

- GPU4 UUID：GPU-7d5a92f6-f7da-b56e-b6f0-586bb28d717d；PCI：0000:3d:00.0。
- NVIDIA报告 `gpu_recovery_action = Reset`、`remapped_rows = GPU requires reset`。
- GPU6报告 `gpu_recovery_action = None`，PCIe错误计数均为0；它被同一个失败进程持有显存。
- PID35437处于D态，等待rwsem_down_write_slowpath；线程SIGKILL和进程SIGTERM均已挂起。
- 本次外围PID35435、35436、35438已用TERM退出；原失败试跑完成记录为0。
- 同一试跑已在60完成；所有结果和日志已保存。
- linxin没有有效管理capability，`sudo -n -l`返回需要密码。Agent没有执行GPU reset。
- Recovery Action仅表明恢复动作，不能据此推断具体故障原因；需要内核Xid日志定位。

## 管理员先读取诊断

```bash
sudo cat /proc/35437/stack
sudo dmesg -T | tail -n 200
nvidia-smi -i GPU-7d5a92f6-f7da-b56e-b6f0-586bb28d717d -q
nvidia-smi --query-compute-apps=gpu_uuid,pid,process_name,used_gpu_memory --format=csv
```

## 定向恢复

管理员确认仅GPU4可安全定向重置、没有其他用户在使用该卡，且符合驱动报告的前提后，可尝试：

```bash
sudo nvidia-smi --gpu-reset -i GPU-7d5a92f6-f7da-b56e-b6f0-586bb28d717d
```

如果返回设备仍被占用、无法定向重置、要求联动其他卡，立即停止；不要改成不带-i的重置，不自动添加其他卡，不卸载驱动或重启主机。GPU reset不保证能解除当前挂起，不能将命令发出当作修复成功。

## 成功判据

```bash
ps -p 35437 -o pid,state,args
nvidia-smi -i 4,6 --query-gpu=index,memory.used,utilization.gpu --format=csv
nvidia-smi -i 4 -q
```

确认35437已退出、GPU4恢复动作为None、残留显存释放后，再做小型CUDA健康验证；未通过前不再次加载模型。GPU6目前没有重置指示，不作为首轮重置目标。

官方说明：https://docs.nvidia.com/deploy/nvidia-smi/ （GPU Recovery Action 与 --gpu-reset）
