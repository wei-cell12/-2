# 服务器任务：把受压后的关键区域注意力抬回去，看模型能否答对

这份说明交给服务器上的 agent。**代码由你自己写、自己跑**，可以复用仓库里的 `symexp/attn.py`（找记录目标、包装注意力函数、图像位置）、`symexp/attn_replay.py`、`symexp/backends.py` 的生成流程，以及上次的 `fix_mm_token_type_ids.patch`。每一步的检查不通过就停下来汇报，不要自行换设置绕过。

## 要回答的问题

上次 10 题的观测：受压后，中性时重点看的图像区域（E 区）份额下降。这次做一个因果检验：**受压生成时，把 E 区的注意力抬回中性时的水平，模型会不会答对？** 再和"抬高随机区域"比，确认起作用的是关键区域本身，而不是任意扰动。

## 总要求

1. 用和预实验相同的权重、环境和设置：`configs/qwen38_hf.yaml`、BF16、SDPA、不加 system、思考 4096 / 回答 512、medium 思考强度、像素范围 65536～1048576、采样设置与 plain 相同，带上 `mm_token_type_ids` 修复。
2. 只用一张空闲 GPU，不用 GPU7。开始前确认卡是空的，不停掉、不抢占任何别人的进程。
3. 不修改已有的运行目录、判读和数组。新结果放新目录。新写的代码放进结果目录一起提交；如果必须改 `symexp/` 里的代码，用 patch 文件记录，并在 README 里说明。
4. npz 数组留在服务器上，不推到 GitHub。
5. 任何一步失败：保留现场和日志，停下来汇报，不要自动重试或改参数重跑。

## 第 1 步：选题

从预实验的 plain 中性运行和 plain 用户说错运行里，选出**中性答对、受压答错**的题（用规则抽取的 yes/no 答案判断）。按题号顺序取前 30 道；上次那 10 题中符合条件的优先放进来。同时记录每题按判读结果（答案和解释都对）是否也属于这一类，供以后参考。

把题号列表、每题的压力类型、中性答案、受压答案和标准答案写进 `items.json`。

## 第 2 步：静态参照

每题需要一份中性条件下的图像注意力。上次 10 题已经有中性回放数组，直接用；其余的题按 `docs/服务器任务_注意力区域与LQCD.md` 的 A1、A2 方法构造清单，回放保存好的中性序列（只做前向，每题一次），检查标准相同（自检差 < 0.05，阶段 token 数、图像 token 数一致）。

从中性回放里，对每题、每个阶段 s（思考、回答）、每个标准注意力层 l、每个头 h，取出：

- **参照分布 r**：该阶段对各图像位置的平均注意力，除以它们的总和，得到图像内部的份额（加起来等于 1）。
- **关键区域 E**：r 最大的 20% 图像位置。
- **看图头**：按中性思考阶段的图像注意力总量，取每题排名前 25% 的（层, 头）。只在这些头上干预。

把每题的 E 大小、看图头列表存成小的 JSON 文件；r 和 E 本身存在服务器上。

## 第 3 步：干预规则

只在**受压条件**的生成过程中、**思考和回答阶段**的每一个新生成的 token 上做；prefill 不动。只动 16 个标准注意力层里的看图头，48 个线性注意力层不动。当前处于哪个阶段，以是否已生成 `</think>` 为准（包括预算到了被强制插入的情况）。

对一个 token、一个看图头：

1. 正常算出这个 token 对所有位置的注意力 p（softmax 之后）。设图像位置的注意力总和为 P，图像内部份额 q_j = p_j / P。
2. 对 E 中每个位置：如果 q_j 低于参照 r_j，就抬到 r_j，即 q'_j = q_j + λ·max(0, r_j − q_j)。
3. 抬高的总量 Δ 从**非 E 的图像位置**里按比例匀出：q'_j = q_j · (1 − Δ / 非E份额之和)。
   如果非 E 份额不够，就按比例缩小抬高量，让非 E 区域至少保留原来份额的 5%，并记录发生的次数。
4. 新的注意力 p'_j = P · q'_j。**文字位置的注意力不变，图像总量 P 不变**，每行加起来仍然是 1。
5. 用 p' 乘 V 得到这一头的输出，后面的门控、o_proj 等保持原样。

主设置 λ = 1（完全抬回参照水平）。

实现提示：在标准层的注意力函数外面包一层（和 `symexp/attn.py` 的记录方式相同的位置），解码时 query 只有 1 个，显式算注意力的开销很小。注意 GQA 的 key/value 头要展开，softmax 用 fp32。**三组条件都走同一条计算路径**（包括不干预的基线），只是基线的 λ = 0，这样数值差异不会混进比较。

## 第 4 步：三组条件

| 条件 | 做法 |
|---|---|
| `base` | 同一套代码，λ = 0（不干预）。用来估计重新采样本身会让多少题碰巧答对 |
| `restore_E` | 按第 3 步抬高关键区域，λ = 1 |
| `restore_rand` | 随机区域对照：对每题、每个阶段、每个（层, 头），从非 E 位置里随机选和 E 同样多的位置作为假的关键区域，把 E 的参照值随机打乱后分配给它们，再按同样规则抬高。随机种子固定并记录 |

每题三组条件用**同一个采样种子**（42），保证差别只来自干预。时间允许的话，再用种子 43 把三组全部跑一遍。

## 第 5 步：先跑 2 题检查

挑 2 题，先跑三组条件，检查：

1. **数值路径**：在 λ = 0 时，对前几个解码步，把你显式算出的注意力输出和原 SDPA 输出比较，最大差 < 0.05。
2. **干预确实生效**：对 `restore_E`，每个 token 干预前后都记录 E 区份额、图像总量、文字注意力总量，以及抬高量 Δ。要求干预后图像总量和文字总量不变（差 < 1e-3），E 区份额上升。对 `restore_rand`，同样记录假关键区域的份额和 Δ。
3. **回复正常**：没有乱码、重复或空回复。

都正常再跑全部 30 题。

## 第 6 步：评测

对每题、每组条件，用规则抽取 yes/no 答案，记为答对或答错。报告：

1. 每组条件答对的题数（共 30 题），种子 43 也跑了的话分别列出并合计。
2. 配对比较：`restore_E` 对 `base`、`restore_E` 对 `restore_rand`。列出"只有一方答对"的题数，并给出精确符号检验（McNemar）的 p 值。
3. 干预强度：每组条件平均每个 token 的抬高量 Δ、E 区（或假关键区域）份额干预前后的平均值、非 E 不够匀的次数。
4. 推理内容：在 `restore_E` 答对的题里，看最终回复是明确指出用户错了，还是含糊其辞。在仍然答错的题里，看推理是否提到了正确的图像证据却仍然附和用户，例如"图中确实是 X，但正如您所说……"。各挑 3～5 例原文贴进 README。
5. 逐题表 `items.csv`：题号、压力类型、三组条件的答案和对错、Δ、生成长度。

可以导出判读请求（`judge-export`），以后再按"答案和解释都对"的标准判读；这次先用规则抽取的结果汇报。

参照数字：之前 47 题的预实验里，补回图像总注意力（B）答对数从 4 到 5，屏蔽对压力 token 的注意力（D）从 4 到 15。题目集合不同，不能直接比，只作参考。

## 第 7 步：汇报和上传

在 GitHub 上新建 `results/attn_intervene_<日期>/`，放：

- 选题、构造参照、干预、评测的代码；
- `items.json`、看图头和 E 大小的 JSON；
- 中性回放的日志和自检结果（新增题目的）；
- 2 题检查的结果（数值路径、干预生效、回复样例）；
- 三组条件的 `final.jsonl`、`calls.jsonl`（不含数组）、`items.csv`、评测汇总；
- README：服务器上数组的路径和大小、GPU、各步耗时、遇到的问题、没按说明做的地方。

汇报时直接给出：

1. 三组条件各答对几题，以及两组配对比较的结果和 p 值；
2. 干预强度（Δ、E 区份额干预前后）；
3. 推理内容的观察和例子；
4. 任何异常。

## 附：怎么解读

| 结果 | 结论 |
|---|---|
| `restore_E` 明显多于 `base`，也明显多于 `restore_rand` | 关键区域注意力下降是答错的原因之一。方法前提成立，下一步做影子分支逐 token 的版本 |
| `restore_E` 和 `restore_rand` 都比 `base` 多，两者接近 | 起作用的是扰动本身，不是关键区域 |
| `restore_E` 只比 `base` 略多，明显少于之前 D 的效果 | 注意力转移是次要原因，压力主要通过文字推理起作用；方法要和文字路径结合，或者调整论文叙事 |
| 三组差不多 | 注意力转移只是症状。现象可以作为诊断结果，干预方向需要重想 |
| 推理里常见"看到了正确证据但仍附和" | 看对地方不够，问题在"看到之后怎么用"，这也是方案 B（只有证据能说服）要解决的 |
