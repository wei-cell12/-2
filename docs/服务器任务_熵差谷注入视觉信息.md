# 服务器任务：熵差谷注入视觉信息（LEAD 风格），三个数据集各 20 题

**做什么**：生成新回答。生成时同步跑熵差分支：提示去掉用户那句话，思考与主回答相同，只读不写。每一步算熵差 ΔH。

**什么时候注入**：在思考里、开头复述段（思考开头到第一个空行）之后，每段连续负熵差里第一次 ΔH ≤ −1 时注入。报警那个 token 照常写出；下一步模型在这个位置读入的向量换成：

  (1 − 0.4) × 按概率加权的词嵌入 + 0.4 × v

每条回答最多注入 5 次。三组，用同一个随机种子：

| 组 | v | 说明 |
|---|---|---|
| base | 不注入 | 报警照样记录 |
| lead | 三个视觉特殊 token 词嵌入的平均 | LEAD 原样 |
| img | 图像位置的视觉特征，按熵差分支这一步的看图注意力加权平均（去掉固定位置），缩放到与原向量一样长 | |

**题目**：每个模型、每个数据集 20 题，用户说错、用户说对各一条。每个模型共 60 题 × 2 × 3 组 = 360 次生成。选题规则：
- 从熵差实验的 50 题里，被带偏和守住各取一半，组内按题号；
- 一组不够时用另一组补，还不够再用其他组补。
- 代码会把清单写进 `selection.json`。

**预计耗时**：熵差分支每一步都要跑，生成大约慢一倍。按以前测的速度（Qwen 约 5 token/秒、Gemma 约 8 token/秒）和这些题原回答的长度估算：
- Qwen 约 30 卡时；
- Gemma 约 25 卡时。

用 `--shard k/n` 分到多张卡上，时间按卡数缩短。

## 规则

- 不要修改任何代码、参数、阈值或清单，也不要额外运行检查命令（下面列出的命令除外）。
- 报错就停下汇报错误信息；不要自己打补丁，不要自动重试。特别是"熵差分支逐步计算与整段计算不一致"这类报错，原样汇报。
- 停进程用 `kill -TERM`，不要用 Ctrl-C；不要停止或抢占别人的进程。只用我指定的服务器和卡。
- 全部在标注用的那份仓库里做。不要上传 npz。
- 不要碰 50 上卡住的 GPU4、GPU6 和那个挂起的进程。
- 判读时不告诉判读者模型名、方法、条件或正确答案。

## 1. 试跑（先做，汇报后等确认）

每个模型 3 题（CQ-003、PV-013、PD-re_used-0009）× 2 种条件 × 3 组 = 18 次生成。

```bash
CUDA_VISIBLE_DEVICES=<指定的卡> python run.py fp-valley --phase run --config <Qwen 本地化配置> --root $TQ --entropy-dir <Qwen 本地化熵差目录> --model-key qwen38 --image-dirs <图像目录> --ids CQ-003 PV-013 PD-re_used-0009 2>&1 | tee $TQ/pilot.log
CUDA_VISIBLE_DEVICES=<指定的卡> python run.py fp-valley --phase run --config <Gemma 本地化配置> --root $TG --entropy-dir <Gemma 本地化熵差目录> --model-key gemma4 --image-dirs <图像目录> --ids CQ-003 PV-013 PD-re_used-0009 2>&1 | tee $TG/pilot.log
```

**汇报**：
- pytest 最后一行；
- 两个 `pilot.log` 里每次生成的那一行（token 数、秒数、报警和注入次数、复述段结束位置、熵差分支核对结果、ClockQA 的结果）；
- 任选一条 img 组的记录，贴出它的 `events` 和 `vis_tokens`。

## 2. 全部（确认后再做）

试跑做完的会自动跳过。有 n 张指定的卡时，第 k 张（k = 0 … n−1）各跑一份：

```bash
CUDA_VISIBLE_DEVICES=<卡> nohup python run.py fp-valley --phase run --config <Qwen 本地化配置> --root $TQ --entropy-dir <Qwen 本地化熵差目录> --model-key qwen38 --image-dirs <图像目录> --shard k/n > $TQ/run_k.log 2>&1 &
# Gemma 同样，--root $TG --model-key gemma4，用 Gemma 的配置和熵差目录
```

## 3. 判读（PathVQA、PENDULUM；ClockQA 自动比对）

每个模型分别做，以 Qwen 为例（Gemma 把 `$TQ` 换成 `$TG`）：

```bash
python run.py fp-valley --phase judge-export --root $TQ      # 生成 $TQ/judge_extract/
```

- **第一步：盲抽取答案。** 判读者按 `$TQ/judge_extract/INSTRUCTIONS.md`，只读 `queue.json` 和 `requests/`，为每条写 `labels/<key>.json`。判读者用之前 PathVQA、PENDULUM 判读时的同一个判读者。不要让判读者读 `private_keymap.json`、records 或任何报告。

```bash
python run.py fp-valley --phase match-export --root $TQ      # 校验并封存第一步的标签，生成 $TQ/judge_match/（只有 PENDULUM）
```

- **第二步：PENDULUM 语义匹配。** 判读者按 `$TQ/judge_match/INSTRUCTIONS.md`，只读 `queue.json` 和 `requests/`，写 `labels/<key>.json`。不要读 `private_order.json`。

```bash
python run.py fp-valley --phase summary --root $TQ --label "Qwen3.8-27B"   # 生成 $TQ/valley_report.md
```
