# 服务器任务：先看再听（读图阶段看不到用户的话，之后用熵差隔离），两个模型 × 三个数据集

**做什么**：生成新回答，Qwen3.8-27B 和 Gemma 4 31B-it，ClockQA、PathVQA、PENDULUM 各 20 题（与熵谷注入实验同一批，程序自动选），用户说错、说对都做。每条做三组，同一随机种子（42）：

- **base**：正常生成。
- **itsm**：ITSM，中性分支对比解码（fp-model2 的实现）。
- **rl（先看再听）**：
  1. **读图阶段**：思考开头由熵差分支来写。它的提示里问题换成模型自己改写的中性问题，看不到用户的话；主分支只把同样的词读进缓存。
  2. **什么时候结束读图阶段**：记录熵差分支每一步对图像的注意力，按段落平均。一段写完时，如果它的看图量降到此前最高那段的一半以下，就在这一段之后切回主分支；最多 512 个词。
  3. **之后**：主分支照常写，熵差片段写完后隔离（后面的词读不到它的内容）。提示和图像都不动。

**中性问题由模型自己改写**（第一步 neutralize，不开思考、贪心，几分钟）。

**规模**：每个模型 3 × 20 × 2 × 3 = 360 次生成。rl 组要同时跑熵差分支，并且要记录注意力，比 base 慢；ITSM 也要同时跑一条中性分支。请用 `--shard k/n` 分到多张卡上。

## 命令

用和 fp-seg、fp-valley 相同的本地化配置、熵差目录和图像目录。`<仓库>` 指这份代码目录的绝对路径。下面以 Qwen 为例，Gemma 把 `qwen38` 换成 `gemma4`、配置和熵差目录换成 Gemma 的。

```bash
cd <仓库> && git pull && git status
python -m pytest tests/test_fp.py -q -rs        # 应全部通过，没有 skipped
RQ=<结果目录>/rl-qwen38-20261109
mkdir -p $RQ
# 1. 中性问题（每个模型一次）
CUDA_VISIBLE_DEVICES=<卡> python run.py fp-rl --phase neutralize --config <Qwen 本地化配置> --root $RQ --entropy-dir <Qwen 本地化熵差目录> --model-key qwen38 > $RQ/neutralize.log 2>&1
# 2. 试跑 3 条（每个数据集 1 题，只跑 rl 组），确认读图阶段正常切换
CUDA_VISIBLE_DEVICES=<卡> python run.py fp-rl --phase run --arms rl --config <Qwen 本地化配置> --root $RQ --entropy-dir <Qwen 本地化熵差目录> --model-key qwen38 --image-dirs <图像目录> --ids CQ-000 PV-000 PD-re_used-0009 > $RQ/pilot.log 2>&1
#    （Gemma 试跑用 --ids CQ-002 PV-013 PD-re_used-0009）
#    试跑没报错就直接接着做第 3 步（试跑完成的记录会自动跳过），同时把 pilot.log 的最后 15 行发给我。
# 3. 全部（每份一组卡；n 份时第 k 份）
CUDA_VISIBLE_DEVICES=<卡> nohup python run.py fp-rl --phase run --config <Qwen 本地化配置> --root $RQ --entropy-dir <Qwen 本地化熵差目录> --model-key qwen38 --image-dirs <图像目录> --shard k/n > $RQ/run_k.log 2>&1 &
# 4. 全部生成完后：PathVQA、PENDULUM 盲判读
python run.py fp-rl --phase judge-export --root $RQ
#    按 $RQ/judge_extract/INSTRUCTIONS.md 写 labels/<key>.json（判读者只读 queue.json 和 requests/）
python run.py fp-rl --phase match-export --root $RQ
#    按 $RQ/judge_match/INSTRUCTIONS.md 写 labels/<key>.json
# 5. 汇总
python run.py fp-rl --phase summary --root $RQ --label "Qwen3.8-27B"
```

中途断了用同一条命令重跑，已完成的会自动跳过。

## 追加（2026-11-09）：空卡多时怎么分（两台服务器，5 张 + 4 张 A800）

同一个模型的所有组写进**同一个结果目录**（记录按组名分文件，互不覆盖），不同进程用 `--arms` 分组、`--shard k/n` 分份。`--arms` 不同的进程各自独立分份（例如 rl 组 3 份：`--arms rl --shard 0/3`、`1/3`、`2/3`）。先做完 neutralize 和试跑，再按下面的优先级开进程：

**优先级 1：主实验**（必须）
- rl 组最慢（同时跑熵差分支并记录注意力），给它最多的卡；
- base、itsm 合在一组（`--arms base itsm`）。

**优先级 2：两个对照**（论文里一定要有）
- `--arms preread`：先读后听（两次调用、预读 64–128 个词），之前只在 ClockQA 上有，这次三个数据集都补上；
- `--arms rl0`：同样的读图阶段，之后不隔离，用来拆开"读图阶段"和"之后的隔离"各自的作用。

**优先级 3：第二个随机种子**（看差别是不是随机波动）
- 新建结果目录（例如 `rl-qwen38-s43-20261109`），把第一个目录里的 `neutralized/` 整个复制过去（只复制，不改），再用 `--seed 43 --arms base itsm rl` 跑。

**建议的分法**（Gemma 如果之前要 2 张卡才能跑一个进程，就按 2 张一组算）：
- 5 张卡的服务器给 Qwen：rl 组 3 份，`base itsm` 1 份，`preread` 1 份；有卡空出来就依次接 `rl0`、第二个种子。
- 4 张卡的服务器给 Gemma：rl 组 2 份，`base itsm preread` 1 份（或各占 1 张，看 Gemma 一张卡能不能跑）；空出来再接 `rl0`、第二个种子。

另外，`docs/服务器任务_一段思考对前文的注意力.md` 末尾"追加"一节的两次回放（first_wrong、first_right，几分钟）还没跑，在 Qwen 那台有卡空出来的间隙跑掉。

所有组都跑完后再做第 4 步判读（一次判读覆盖目录里的全部组），然后汇总。第二个种子的目录同样判读、汇总、上传到 `results/read_listen_20261109/{qwen38,gemma4}_s43/`。
