# 服务器任务：熵差片段隔离（整段思考里读不到靠用户那句话写出来的片段），Qwen · ClockQA 20 题

**做什么**：生成新回答（只做 Qwen3.8-27B，ClockQA）。

1. **熵差分支**：生成时同步跑一条分支，提示里的问题换成模型自己改写的中性问题（仓库里已有：`results/compare_cq_20261029/a100/neutralized/`），思考与主回答相同，只读不写。每一步算熵差 ΔH，从思考开头一直算到思考结束。
2. **熵差片段**：每段连续负熵差里只要有一步 ≤ −1，这一整段就是熵差片段。一段写完（熵差回到 ≥ 0）之后才开始隔离。
3. **重复内容**：熵差片段里出现的时间（时:分），模型在思考里任何地方再写出同一个时:分，这几个词也一起隔离。
4. **seg 组**：思考里每个词、每个标准注意力层，对以上位置的注意力权重乘以 0，不重新归一化：注意力分布不变，只是读不到内容。提示（包括用户那句话）和图像都不动。思考结束后照常写答案，熵差分支也停掉。
5. **正常生成**不重复跑，沿用回声隔离实验里同一随机种子（42）的 base 组。

**题目**：与回声隔离、fp-maskq 相同的 20 题，用户说错、说对都做，共 40 次生成。

**预计耗时**：熵差分支要跑完整段思考，生成大约慢一倍。一个进程约 3–5 小时；可以用 `--shard k/n` 分多份并行。

## 规则

- 不要修改任何代码、参数、阈值或清单，也不要额外运行检查命令（下面列出的命令除外）。运行前确认 `git status` 干净。
- 用之前跑通的同一个 Python 环境（51 上是 `conda activate gemma4`），不要安装或升级任何库。
- 报错就停下，原样汇报错误信息；不要自己打补丁，不要自动重试。
- 停进程用 `kill -TERM`，不要用 Ctrl-C；不要停止或抢占别人的进程。只用我指定的服务器和卡。
- 全部在标注用的那份仓库里做。不要上传 npz。
- 不要碰 50 上卡住的 GPU4、GPU6 和那个挂起的进程。

## 命令

用和 fp-echo 相同的 Qwen 本地化配置、熵差目录和图像目录。`<仓库>` 指这份代码目录的绝对路径。

```bash
cd <仓库> && git pull && git status
python -m pytest tests/test_fp.py -q -rs        # 应全部通过，没有 skipped
SQ=<结果目录>/seg-qwen38-20261109
mkdir -p $SQ
# 每份一组卡；n 份时第 k 份（k = 0 … n−1）
CUDA_VISIBLE_DEVICES=<卡> nohup python run.py fp-seg --phase run --config <Qwen 本地化配置> --root $SQ --entropy-dir <Qwen 本地化熵差目录> --model-key qwen38 --neutral-dir <仓库>/results/compare_cq_20261029/a100/neutralized --image-dirs <图像目录> --shard k/n > $SQ/run_k.log 2>&1 &
# 全部完成后
python run.py fp-seg --phase summary --root $SQ --label "Qwen3.8-27B · ClockQA" --echo-root <仓库>/results/echo_isolate_20261108/qwen38 --maskq-root <仓库>/results/maskq_20261108/qwen38
```

中途断了用同一条命令重跑，已完成的会自动跳过。
