# 服务器任务：熵差的参照不带复述段时，读图那一段会不会出现熵差谷（离线回放，不生成）

**做什么**：熵差实验用的那些受压回答（每个模型 3 个数据集 × 50 题 × 用户说错/说对 = 300 条），每条用同一段文字回放三次，逐词算"下一个词"分布的熵：

1. 完整提示（有用户那句话）+ 原回答；
2. 提示去掉用户那句话 + 原回答（就是现在的熵差分支，保留开头复述段）；
3. 提示去掉用户那句话 + 原回答删掉开头复述段（锚点一的参照分支）。开头第一段没提 user 时不删，第 3 次和第 2 次相同，不重复算。

由此得到两种熵差：现在的熵差 ΔH1 = 1 − 2，新熵差 ΔH2 = 1 − 3。之后在 CPU 上汇总：
- 读图段（复述段之后 128 个词）里两种熵差的大小；
- 第一次报警的位置：是否早于模型再次写出用户的答案、是否早于模型提到 user。

**为什么做**：现在的熵差分支保留了复述段（里面已有用户的答案），所以模型按用户答案读图的那一段熵差接近 0，报警要等到模型写 "The user says" 时才出现，那时结论已经写下了。这次检验换成不带复述段的参照，看能不能在读图时就报警。

**预计耗时**：只做前向，不生成。每条 2–3 次前向，每个模型大约 1–2 卡时，可用 `--shard k/n` 分多份并行。

## 命令

用和熵谷注入、锚点一相同的本地化配置、熵差目录和图像目录。

```bash
cd <代码目录> && git pull && git status
python -m pytest tests/test_fp.py -q -rs        # 应全部通过，没有 skipped
EQ=<结果目录>/refent-qwen38-20261108
EG=<结果目录>/refent-gemma4-20261108
mkdir -p $EQ $EG
# 每份一组卡；n 份时第 k 份（k = 0 … n−1）
CUDA_VISIBLE_DEVICES=<卡> nohup python run.py fp-refent --phase replay --config <Qwen 本地化配置> --root $EQ --entropy-dir <Qwen 本地化熵差目录> --model-key qwen38 --image-dirs <图像目录> --shard k/n > $EQ/replay_k.log 2>&1 &
CUDA_VISIBLE_DEVICES=<卡> nohup python run.py fp-refent --phase replay --config <Gemma 本地化配置> --root $EG --entropy-dir <Gemma 本地化熵差目录> --model-key gemma4 --image-dirs <图像目录> --shard k/n > $EG/replay_k.log 2>&1 &
# 全部回放完后
python run.py fp-refent --phase analyze --root $EQ --label "Qwen3.8-27B"
python run.py fp-refent --phase analyze --root $EG --label "Gemma 4 31B-it"
```

日志每条会打印"与熵差实验对比"的熵差值：前两次回放应该与熵差实验当时算出的熵基本一致，中位差应在 0.01 以下。如果中位差明显偏大（例如 > 0.05），停下汇报。

中途断了用同一条命令重跑，已完成的会自动跳过。
