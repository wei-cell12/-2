# 服务器任务：对照组——生成思考的前 128 个词时，文本侧看不见提示里的用户那句话（不碰图像注意力）

**做什么**：生成新回答（ClockQA）。

- **mask 组**：生成思考的前 128 个词时，在每个标准注意力层里，把当前词对"用户那句话"那几个 token 的注意力置零，再重新归一化。图像和其他位置按原有比例分走这部分注意力，不对图像做任何人工放大。128 个词之后照常生成。
- **base 组**：不改。
- 两组用同一个随机种子（42）。

**记录**：
- 前 64 个词的看图总量和关键区份额，以及与中性回答的 JSD。关键区 = 原模型中性回答前 64 个词里注意力最高的 20% 图块，每题回放一次中性回答来确定。
- 第一次读数：思考里模型自己写出的第一个时间。
- 最终答案。
- 前 128 个词里有没有写出用户给的时间。mask 组如果写出了，说明用户的信息从挡不住的路漏了进来：Qwen 的线性注意力层，以及提示里那句话之后的模板 token。

**题目**：与熵谷注入、锚点一相同的 ClockQA 选题（每个模型被带偏 10 题、守住 10 题），用户说错、说对都做。每个模型 20 题 × 2 种条件 × 2 组 = 80 次生成，外加 20 次中性回答回放。

**预计耗时**：每个模型一个进程约 3–4 小时；可以用 `--shard k/n` 分多份并行。

## 规则

- 不要修改任何代码、参数、阈值或清单，也不要额外运行检查命令（下面列出的命令除外）。运行前确认 `git status` 干净。
- 用之前熵谷注入、锚点一跑通时的同一个 Python 环境（51 上是 `conda activate gemma4`），不要安装或升级任何库。
- 报错就停下汇报错误信息；不要自己打补丁，不要自动重试。
- 停进程用 `kill -TERM`，不要用 Ctrl-C；不要停止或抢占别人的进程。只用我指定的服务器和卡。
- 全部在标注用的那份仓库里做。不要上传 npz。
- 不要碰 50 上卡住的 GPU4、GPU6 和那个挂起的进程。

## 命令

用和熵谷注入、锚点一相同的本地化配置、熵差目录和图像目录。熵差目录的 manifest 里要能找到这些题的中性回答（字段 `neutral_source`，按 `neutral_sha256` 核对）。

```bash
cd <代码目录> && git pull && git status
python -m pytest tests/test_fp.py -q -rs        # 应全部通过，没有 skipped
KQ=<结果目录>/maskq-qwen38-20261108
KG=<结果目录>/maskq-gemma4-20261108
mkdir -p $KQ $KG
# 每份一组卡；n 份时第 k 份（k = 0 … n−1）
CUDA_VISIBLE_DEVICES=<卡> nohup python run.py fp-maskq --phase run --config <Qwen 本地化配置> --root $KQ --entropy-dir <Qwen 本地化熵差目录> --model-key qwen38 --image-dirs <图像目录> --shard k/n > $KQ/run_k.log 2>&1 &
CUDA_VISIBLE_DEVICES=<卡> nohup python run.py fp-maskq --phase run --config <Gemma 本地化配置> --root $KG --entropy-dir <Gemma 本地化熵差目录> --model-key gemma4 --image-dirs <图像目录> --shard k/n > $KG/run_k.log 2>&1 &
# 全部完成后
python run.py fp-maskq --phase summary --root $KQ --label "Qwen3.8-27B · ClockQA"
python run.py fp-maskq --phase summary --root $KG --label "Gemma 4 31B-it · ClockQA"
```

中途断了用同一条命令重跑，已完成的会自动跳过。
