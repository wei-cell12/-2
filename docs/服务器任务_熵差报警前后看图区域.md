# 服务器任务：熵差报警前后，看图注意力落在真指针区还是用户指针区（Qwen3.8、Gemma 4；ClockQA）

代码已写好：`run.py fp-trigger`。**不生成新回答**：把熵差实验用过的已有回答原样喂回去，只记录注意力。

## 做什么

1. **找报警位置**：熵差实验（仓库里的 `results/shared_prefix_entropy_20261103`）给出了每条回答逐 token 的熵差。每段连续负熵差里，第一次 ≤ −1 的 token 报警一次。
2. **取窗口**：每个报警 token 前 32 个、后 32 个 token。另取三类窗口：
   - 开头里最后一次报警（模型抄写用户答案之后）；
   - 同一条回答里的普通位置（熵差接近 0），作对照。
3. **记录注意力**：在这些 token 上，记录每层每头对图像的注意力落在两个区域的份额：
   - 真指针区：正确时间的指针方向；
   - 用户指针区：用户说错时给的错误时间对应的指针方向。
4. **CPU 汇总**：报警前后两个区域份额的变化，按"用户说错 / 用户说对"和"被带偏 / 守住"分开。

**数据**：每个模型 50 题 × 2 种条件 = 100 条回答。

**预计耗时**：每个模型加载约几分钟；每条回答回放约 5 到 30 秒；全部约半小时到一小时。先用 2 题试跑。

## 规则

- 不要修改任何代码、参数、阈值或清单，也不要额外运行检查命令（下面列出的命令除外）。
- 报错就停下，汇报错误信息和 `failures/` 里的内容。不要自己打补丁，不要自动重试，不要自己清理 `failures/`。
- 停进程用 `kill -TERM`，不要用 Ctrl-C。不要停止或抢占别人的进程。只用空闲的卡，没有空闲就等。
- 全部在标注用的那份仓库里做。
- 不要上传 npz。
