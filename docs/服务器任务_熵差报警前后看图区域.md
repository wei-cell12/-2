# 服务器任务：熵差报警前后，看图注意力落在哪里（Qwen3.8、Gemma 4；ClockQA、PathVQA、PENDULUM）

代码已写好：`run.py fp-trigger`。**不生成新回答**：把熵差实验用过的已有回答原样喂回去，只记录注意力。

## 做什么

1. **找报警位置**：熵差实验（仓库里的 `results/shared_prefix_entropy_20261103`）给出了每条回答逐 token 的熵差。每段连续负熵差里，第一次 ≤ −1 的 token 报警一次。
2. **取窗口**：每个报警 token 前 32 个、后 32 个 token。另取两类窗口：
   - 开头里最后一次报警（模型抄写用户答案之后）；
   - 同一条回答里熵差接近 0 的普通位置，作对照。
3. **记录**：在这些 token 上记录每层每头对图像的注意力。
   - 三个数据集都算："前焦点"（报警前注意力最集中的 20% 图块）在报警后还剩多少，以及前后看图分布的 JSD。
   - ClockQA 另算两个区域的份额：真指针区（正确时间的指针方向）、用户指针区（用户说错时给的错误时间的指针方向）。
4. **CPU 汇总**：按数据集、"用户说错 / 用户说对"、"被带偏 / 守住"分开列。

**数据**：每个模型 3 个数据集 × 50 题 × 2 种条件 = 300 条回答。

**题目、消息原文、原回答路径和图像**：都从熵差实验的 `manifest.json` 里读。
- 原回答和图像都按熵差实验记下的 SHA 核对，不一致就报错停下。
- 熵差实验记下的图像路径在本机不存在时，按 SHA 在 `--image-dirs` 给的目录里找。

**试跑**：每个数据集 2 题，一题被带偏、一题守住，共 6 题 12 条回答。
- ClockQA：CQ-003、CQ-009
- PathVQA：PV-013、PV-001
- PENDULUM：PD-re_used-0009、PD-re_used-0006

**预计耗时**：
- 试跑：加载模型几分钟，12 条回答约 5 分钟。
- 全部：每条约 5 到 30 秒，单卡约 1 到 2 小时；多卡按卡数缩短。
